EXAMPLE WORKFLOW

From request to a reviewable WordPress draft

“Create a draft landing page for the weekend offer, using the existing brand style.” This is a bounded example of the workflow—not a live operation or an invented activity feed.

1. Request

You describe the outcome and the boundaries that matter.

2. Plan

3. Approval

4. Result

WordPress contains a reviewable draft, and the activity is recorded.

Why the workflow stops at a draft

A draft makes the first useful result inspectable before publication. You can review the page, confirm the activity record, and decide whether to continue.

FIRST CONNECTION

Start read-only. Earn the next action.

Use the current connection endpoint shown inside your installed MCPWP settings. Keep the API key private and grant only the scope needed for this connection.

  1. Install and activate MCPWP.
  2. Create a scoped API key in WordPress.
  3. Connect your chosen AI client using the current MCPWP endpoint shown in the plugin.
  4. Verify the connection with a read-only site-information request.
  5. Create a draft before attempting publication.
